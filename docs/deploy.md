# Deploying VisionMirror

Goal: a public **HTTPS** URL the Android app can call. Render is the easiest path and is described step by step. Railway and Fly are covered briefly at the end.

> Nothing here has been run on a real host yet. The Dockerfile has not been built (Docker was unavailable on the dev machine), and the Render blueprint has not been applied. The first deploy is the real test, which is what the smoke test below is for.

## Before you start

1. **Put the project in its own GitHub repository.** The code lives in `visionmirror/` (this folder: `backend/`, `docs/`, `render.yaml`). The Documents folder you work in is a much bigger git repository, which Render cannot sensibly deploy. Create a new empty GitHub repo, then:
   ```bash
   cd path/to/vissionmirror
   git init && git add . && git commit -m "VisionMirror backend"
   git branch -M main
   git remote add origin https://github.com/YOUR-NAME/visionmirror.git
   git push -u origin main
   ```
   Check `git status` first: `.env` must **not** be listed (it is ignored). Never commit keys.
2. **Create a fresh Gemini key** at https://aistudio.google.com/apikey and delete the one pasted into earlier chats.
3. Decide your frontend origin (the web app's exact URL, e.g. `https://visionmirror.vercel.app`). The Android app does not need this.

## Deploy on Render (free tier)

1. Sign in at https://render.com with GitHub.
2. **New + → Blueprint**, pick your repository. Render reads `render.yaml` and proposes two things: the web service `visionmirror-api` and a Key Value (Redis) store `visionmirror-redis`.
3. It asks for the two values marked `sync: false`:
   - `GEMINI_API_KEY`: your new key.
   - `CORS_ORIGINS`: your frontend's exact origin, or leave blank if only the Android app uses the API.
4. **Apply.** The first build takes a few minutes. When the service shows *Live*, your URL is `https://visionmirror-api.onrender.com` (the name may get a suffix; see the dashboard).
5. Run the smoke test (below).

`SECRET_KEY` is generated by Render and `REDIS_URL` is wired automatically. HTTPS is automatic; Render also redirects HTTP to HTTPS.

### Free-tier behaviour you should know

- **The API sleeps after ~15 minutes without traffic.** The first request afterwards takes about a minute. For a live demo, open `/v1/health` a few minutes before you present, or use a paid instance. The app should show a "waking up" message for a slow first call. (The smoke test waits for this.)
- **The free Redis does not persist data.** That suits this app, which keeps sessions for only 10 minutes, but a restart drops active sessions and rate-limit counters. Users just take a new photo.
- Free Key Value instances can be removed after a period of inactivity; recreate it from the blueprint if so.

## Environment variables

| Variable | Required | Default | Purpose |
|----------|----------|---------|---------|
| `SECRET_KEY` | **yes** | none | Signs tokens. 32+ random characters. Changing it logs every device out. Render generates it. |
| `REDIS_URL` | **yes** | `redis://localhost:6379/0` | Redis connection. Render fills it from the Key Value store. |
| `VISION_PROVIDER` | yes | `mock` | `gemini`, `anthropic`, or `mock` (canned output, no AI calls). |
| `GEMINI_API_KEY` | if gemini | none | Google AI Studio key. |
| `GEMINI_MODEL` | no | `gemini-3.5-flash` | Check the model still exists; Google retires names. |
| `GEMINI_THINKING_LEVEL` | no | `medium` | `low` is ~5 s but missed an obvious stain in testing; `medium` takes ~12-15 s and caught it. Don't lower it without re-testing on flawed photos. |
| `ANTHROPIC_API_KEY` | if anthropic | none | Paid; separate from a Claude subscription. |
| `VISION_MODEL` | no | `claude-sonnet-5-5` | Anthropic model. |
| `VISION_EFFORT` | no | `medium` | Anthropic thinking depth: `low`/`medium`/`high`. |
| `TRUST_PROXY_HEADERS` | **set `true` on a host** | `false` | Use the real client IP for rate limits. Only behind a proxy you control. |
| `CORS_ORIGINS` | for web frontends | empty | Comma-separated exact origins. No `*`. |
| `DAILY_AI_CALL_LIMIT` | recommended | `500` | Global AI calls (describe + ask) per UTC day. Your spending ceiling. |
| `RATE_DESCRIBE_DEVICE_PER_MIN` / `_IP_` | no | 6 / 20 | Describe limits. |
| `RATE_ASK_DEVICE_PER_MIN` / `_IP_` | no | 20 / 60 | Ask limits. |
| `RATE_GENERAL_DEVICE_PER_MIN` / `_IP_` | no | 60 / 120 | Everything else. |
| `RATE_AUTH_IP_PER_MIN` | no | 20 | Token minting, per IP. |
| `TOKEN_TTL_SECONDS` | no | `86400` | Token lifetime. |
| `SESSION_TTL_SECONDS` | no | `600` | How long a photo is kept. |
| `MAX_IMAGE_BYTES` | no | `5242880` | Upload limit (5 MB). |
| `LOG_LEVEL` | no | `INFO` | JSON logs go to stdout; read them in the host's log viewer. |

If many people share one network (a school, a competition venue), the per-IP limits are shared too. Raise `RATE_DESCRIBE_IP_PER_MIN` for the demo.

## Smoke test

Run it from your computer against the live URL:

```bash
cd backend
pip install -r requirements.txt                      # httpx and Pillow are enough
python scripts/smoke_test.py https://YOUR-SERVICE.onrender.com \
    --photo ../samples/street_woman.jpg --origin https://your-frontend.example
```

It checks health and `/docs`, security headers (and HSTS over HTTPS), that requests without a token are rejected, token issuance, that an unlisted browser origin gets no CORS permission, and, unless you pass `--skip-ai`, the full describe → ask → delete → "gone" flow. The AI part uses **2 AI calls**. Without `--photo` it uses a generated image, which a real AI will correctly call unusable ("no person"); use a real photo to exercise ask and delete. Exit code is 0 only if everything passed.

## Is it safe to demo? Checklist

- [ ] `.env` was never committed (`git log --all -- backend/.env` prints nothing).
- [ ] Old, chat-pasted API keys are deleted; the new one lives only in the host's dashboard.
- [ ] `DAILY_AI_CALL_LIMIT` is set to something you are happy to pay for (or stay on a free key).
- [ ] `TRUST_PROXY_HEADERS=true` on the host.
- [ ] `CORS_ORIGINS` lists only your real frontend (or is empty).
- [ ] Smoke test passes against the HTTPS URL.
- [ ] You know the Gemini free tier may use photos to improve Google products (see `privacy.md`); demo with your own or consented photos.

## Gemini free-tier quota

The free tier allows only a few requests per minute and a limited number per day, and the limits change. During testing, back-to-back calls produced `429` and `503` from Google (the API returns `502 ai_unavailable` to the app and retries up to twice first). Fine for a demo with one presenter; not for a crowd. If you expect traffic, enable billing on the Google key or use Anthropic, and set `DAILY_AI_CALL_LIMIT` to match what you can afford.

## Troubleshooting

| Symptom | Likely cause |
|---------|--------------|
| Service stuck "Deploying", health check fails | Check logs. A missing `SECRET_KEY` or `GEMINI_API_KEY` stops startup with a clear message. |
| `/v1/describe` returns 502 `ai_unavailable` | Provider error. Logs show the HTTP status only. 404 = model name retired (change `GEMINI_MODEL`), 429/503 = busy or quota. |
| Everyone gets 429 quickly | `TRUST_PROXY_HEADERS` is `false`, so all users share the proxy's IP. Set it to `true`. |
| `503 service_unavailable` | Redis unreachable. Check the Key Value store and `REDIS_URL`. |
| Browser app shows a CORS error | The frontend's exact origin (scheme, host, port, no trailing slash) is missing from `CORS_ORIGINS`. |
| First request takes ~1 minute | Free-tier cold start; see above. |

## Other hosts

**Railway:** New Project → Deploy from GitHub repo, set the service's root directory to `backend` (it detects the Dockerfile). Add the **Redis** plugin and set `REDIS_URL` to its connection variable (`${{Redis.REDIS_URL}}`). Add the variables from the table above, including `TRUST_PROXY_HEADERS=true`. Generate a public domain under Settings → Networking.

**Fly.io:** from `backend/`, run `fly launch` (accept the Dockerfile, set internal port 8000), create Redis with `fly redis create` and set its URL via `fly secrets set REDIS_URL=...`, then `fly secrets set SECRET_KEY=... GEMINI_API_KEY=... TRUST_PROXY_HEADERS=true VISION_PROVIDER=gemini` and `fly deploy`. Fly serves HTTPS on `https://APP.fly.dev`. Fly requires a payment card on file.

For all hosts the container listens on `$PORT` (default 8000) and the health check path is `/v1/health`.
